## RCA — 自定义域名 eztyv.com 绑定 + SSL (corporate-web-95)

### 现象
- `https://eztyv.com` 访问报 SSL 连接错误（curl exit 35 = SSL connect error）。
- 用户已在阿里云 DNS 添加 A 记录：eztyv.com / www.eztyv.com → 162.159.142.117 / 172.66.2.113（Cloudflare anycast IP），公共 DNS 已生效。
- 此前已成功 redeploy（run ac80293e，status=success），线上应用正常：https://corporate-web-95.emergent.host。

### 根因
平台侧该域名 **从未被绑定到本部署**。
- `list_domains` 与 `check_domain_status` 返回 `domains: []` —— 即 eztyv.com / www.eztyv.com 都没有被添加到 deployment `corporate-web-95`。
- 该应用 `frontend_type = cloudflare`。自定义域名的 SSL 证书是在用户于 Deployment Panel → Domains 添加域名、平台完成验证后，由 Cloudflare 自动签发的。
- 仅在 DNS 侧把 A 记录指向 Cloudflare IP 并不会触发证书签发 —— Cloudflare 边缘没有为该 hostname 配置自定义主机名，因此 TLS 握手失败 → curl exit 35。这是预期行为，不是部署故障。

### 修复（需在 UI 操作，本 agent 无绑定/解绑域名的工具）
1. 打开 Deployment Panel → Domains（域名）标签页。
2. 添加 `eztyv.com`，再添加 `www.eztyv.com`。
3. 平台会**针对每个域名显示需要添加的确切 DNS 记录**（类型/主机记录/记录值）。请以平台显示的记录为准，在阿里云逐字添加 —— 平台给出的记录可能与当前已配置的记录不同（例如 CNAME 或带验证用的 TXT 记录）。
4. 添加并保存后，平台会进行验证（通常数小时内），验证通过后 Cloudflare 自动签发 SSL 证书，`https://eztyv.com` 即可访问。
5. 验证成功后平台会自动把 `REACT_APP_BACKEND_URL` 切到自定义域名并触发一次 redeploy。

### 部署状态确认
线上部署健康，运行的是 run `ac80293e`（redeploy，成功，2026-10-07）。无需再次 redeploy 来“修复” SSL —— SSL 问题的唯一前置是先在 UI 绑定域名。
